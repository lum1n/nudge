# 3. Extensions are Pi Durable extensions with a small manifest

Nudge grows through extensions, so writing one should need nothing beyond Pi Durable's own `Extension` (tools, prompt sections, hooks, wraps, tasks). An extension made with `defineNudgeExtension` adds only what Nudge needs around it: a `name`, a `version`, an optional TypeBox `settings` schema, and a `setup(host)` that returns the Pi Durable parts plus optional PII `detectors`. `setup` takes the place of an install hook: it runs once per assistant when it opens and again on every reload, gets its settings checked and defaulted from the config, and closes over them in its tools and sections. A plain Pi Durable extension works too, without settings or detectors.

Extensions are installed into the assistant's registry before the Harness opens, so their tasks resume with it. Every conversation selects every installed extension (Pi Durable's default), so the config decides what the assistant can do, not each room. Reloading (`nudge reload`, SIGHUP) sets every extension up first and only then swaps them into the registry by name, so one that fails changes nothing; conversations pick the change up at their next turn. Only the entry module is imported again on reload; what it imports stays in Node's module cache.

Detectors from extensions run after the built-in ones, in the same `Models` wrapper (ADR 0002), so nothing an extension adds can bypass redaction.

## API version and the assistant extensions see

`@nudge/core` is private and unpublished for now, so every extension builds against the core in this repository. Extensions from elsewhere still need to know what they may rely on, so the manifest has an optional `apiVersion`, `major.minor`, naming the version of the extension API it was written against; core exports its own as `EXTENSION_API_VERSION`. The major goes up when something an extension may rely on (`defineNudgeExtension`, `ExtensionHost`, `ExtensionParts`, `ExtensionAssistant`) changes or goes away, the minor when something is added. Before `setup` runs, an extension whose major differs, or that needs a newer minor, is refused like one whose setup throws: the assistant opens without it and lists it as broken, saying which version it needs. A missing `apiVersion` is taken as compatible for now; every extension in this repository declares one. Whether and how core is published is a separate decision.

`host.assistant()` and `host.whenOpen()` give extensions an `ExtensionAssistant`: the members of `Nudge` that extensions use (players, profiles, rooms, room extensions, conversations, private values, `changes`) and a `harness` narrowed to documents, conversations and tasks. It is the same object as the assistant, narrowed only in its type, so an extension can still key maps by it and nothing changes at run time; a member leaves `ExtensionAssistant` only with a new major. An extension that needs more of `Nudge` adds it here instead of reaching past the type.
