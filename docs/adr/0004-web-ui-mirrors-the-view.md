# 4. Browser mirrors the pi-durable view; assistant-ui owns rendering

The web UI needs the same multiplayer view every CLI client sees: others' messages and tool calls live, not just its own request/response. A chat library's own transport would need translating pi-durable's `ConversationView` into another protocol and back — TanStack AI's AG-UI stream fakes other people's runs as its own; the Vercel AI SDK's `ChatTransport` is per-request and drops frames with no matching request id. Instead the server streams the room's `ConversationView` once, then its exact [Chord](https://github.com/earendil-works/pi/tree/main/packages/chord) ops per commit (`?format=view` on the existing agent-events stream), and the browser keeps an immutable mirror of it with `@earendil-works/chord/delta`; a pure reader turns that into messages, a queue and a status line, the same room a CLI client sees.

[assistant-ui](https://www.assistant-ui.com)'s `useExternalStoreRuntime` renders that thread, composer, cancel and queue/steer without owning the data itself, so the mirror stays the one source of truth. Its `assistant-ui add` component kit (shadcn, radix, class-variance-authority) is skipped for hand-rolled Tailwind classes on its headless primitives instead, to match the rest of the app rather than add a second styling system. Both pi-durable's view shape and assistant-ui's 0.x API are exact-pinned and change without notice; a server-side test replays a recorded scenario and checks a fresh run's shape against it, so a pi-durable upgrade that changes the view fails there first, not in the browser.
