# 5. Clients speak a Nudge-owned protocol; the server projects the room

Supersedes ADR 4 for the wire format; assistant-ui still renders the web thread.

Nudge runs on a host and is used from native clients on iOS, Android and macOS, from Python bots, and from the web UI. ADR 4 streamed pi-durable's `ConversationView` and Chord ops to the browser, which rebuilt the chat from Pi's docs and refetched memory, approvals and nudges when it saw certain tool names finish. Every other client would have to repeat that in its own language and break on each pi-durable upgrade, which is pinned exactly because its API changes without notice.

Instead the host projects each room into a Nudge-shaped `RoomView`: the room and its members, a timeline of user messages, fired nudges, approvals, answers (text, reasoning and tool parts) and compaction markers, whether an answer is running, the queue, and the room's approvals, memory and nudges. A `HomeView` holds the player's rooms with a little state each. The projection lives in `@nudge/protocol`, which does no IO, so the server, the TypeScript client and its tests share one implementation, and pi-durable's shapes stop at that package.

One WebSocket per client carries subscriptions to `home` and `room:<id>`. For each subscription the server remembers the view it last sent and sends the difference to the current one as a few plain JSON operations (`set`, `del`, `append`, `splice`) at most every ~50 ms. A slow client gets fewer, larger patches and nothing is queued for it. Every frame has a `seq` per subscription; a client that sees a gap subscribes again and gets a fresh snapshot. There is no resume from a cursor in this version; native clients keep the last snapshot on disk for a quick start.

Commands (send, abort, decide, remember, forget, cancel a nudge, rooms) stay plain HTTP, made idempotent by the client's `requestId`. They then work from a phone's background task or a notification action without a socket, and from a bot with nothing more than an HTTP client. Devices sign in with one-time pairing codes rather than a token in a QR code, so each device gets its own client id and a lost phone is revoked on its own.

Everything is under `/v1`, and `hello` names the protocol version. The JSON Schema is generated from the TypeBox types in `@nudge/protocol`. Native clients share one Rust core (connection, reconnect, patches, offline cache, send queue) with Swift, Kotlin and Python bindings made by UniFFI; it is tested against the same recorded sessions as the TypeScript client, so the two can't drift unnoticed. The `/a` routes and ADR 4's formats are removed once the web UI and CLI have moved over. Extension sockets (the browser's live view) stay extension-defined. The details are in [docs/protocol/v1.md](../protocol/v1.md).
