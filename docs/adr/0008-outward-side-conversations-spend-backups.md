# 8. Rooms speak outward, work in side conversations, keep to a budget, and back up whole

Nudge's people aren't always in a tab with the room open, so the assistant has to reach them where they are: a phone's notifications, Telegram, Signal, Matrix. It also does work nobody asked for in the moment (watches, budget warnings), which must not clutter the room or run up a bill. And a household's assistant holds things worth not losing.

**Room events are the one outward hook.** `RoomEvents` reads the Harness's commits and turns them into `answer` events (a finished answer's text, what prompted it: a message, a fired nudge or an approval's outcome, and whether it finished) and `approval` events (one newly pending). Extensions get them through `onRoomEvent` in the rooms they are on in; hosts through `Nudge.events`. Events aren't replayed: what happens while the host is down is gone, and a pending approval is announced once. Web Push and every chat bridge are built on it, so a new way out needs no new core code. What goes out leaves Nudge's redaction behind; Web Push encrypts it for the browser and names only the room unless `push.preview` says otherwise, and the bridges say plainly that the chat service can read what passes through.

**A chat account is a client.** A bridge links an account by a pairing code (`/link`), which creates a token like any app's. Revoking the token unlinks the account, and every message checks for it. A direct chat talks to the player's own room; a group talks to the room a linked member picks. Approvals can be decided from the chat by members of the room. Extensions reach the assistant itself through `ExtensionHost.assistant()`; in-process extensions could already reach each other (ADR 6), so this opens nothing that was closed.

**Background work runs in side conversations.** A side conversation has its room's model, instructions and extensions, and a transcript of its own. `roomOf` resolves it to the room, so tools, sections, memory, connectors and browser logins work there as in the room, but nothing in it shows in the room or raises room events. A watch is a durable timer that resets its side conversation, asks for the items that match (each with a stable key) and tells the room, as a fired nudge, only about keys it hasn't seen. A check that fails records why rather than reporting "nothing found".

**Spend is booked from Pi Durable's own ledger.** `Spending` follows each conversation's `pi.usage` (the assistant's requests and what tools report about theirs) from the totals at open, so a restart books nothing twice. It books to the month in the assistant's time zone, to the room (side conversations count for theirs) and to the player whose message is being answered (nudges and watches count for no one). A player past `perPlayerUsd` has their messages refused. Past `monthlyUsd`, `RedactingModels` sends no request at all, background work included. At `warnAt` the player, or the admins, hear about it once a month. Model calls an extension makes without reporting usage aren't counted.

**A backup is everything needed to start again, under one key.** Databases are copied with `VACUUM INTO` over a reading connection of their own, consistent while the assistant writes, and an encrypted one stays encrypted. Its key file, the extensions' data (their secret stores included), the push keys and the config go in the same file, sealed in 1 MiB AES-256-GCM chunks under the backup key, with the last chunk marked so a cut file fails. So the backup key alone restores a lost machine, and it must be kept off that machine. Restore unpacks into a directory of its own and checks every file's hash. Getting copies off the machine is left to the folder `backup.dir` points at (a synced folder, a mounted share) or to rclone.

Other privacy choices made along the way: images and scanned PDFs are kept but not read, because reading them means sending them to a provider that redaction can't cover; voice is left out for the same reason. **Model view** shows anyone in a room the request its next turn sends, with placeholders where the values were, so the promise of ADR 2 can be checked rather than trusted. An optional detector (`extensions/ner`) adds names and street addresses from name lists and rules, keeping to no local models.
