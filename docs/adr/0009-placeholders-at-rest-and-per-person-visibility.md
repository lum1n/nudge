# 9. History holds placeholders; each person sees what is theirs to see

ADR 2 kept personal values from the model but stored them raw, and ADR 7 encrypted the file. Two things were still missing. In a shared room, everyone saw everything: there was no way to tell the assistant something the others in the room shouldn't read. And forgetting a value was impossible, because the transcript held it in many places.

**The transcript, and what Nudge stores for people, holds placeholders.** Messages are redacted before they are submitted, models' answers are committed as the model wrote them (with placeholders, `RedactingModels` no longer puts values back), and every tool sits between the two (`withToolValues`): its arguments get the values back, since it acts on them, and what it returns, prints and reports is redacted before the Harness stores it. Tools that only store what they are given, such as `remember`, `schedule_nudge`, the lists and `add_watch`, are marked `keepsPlaceholders` and get the placeholders instead. Memory, approvals (summary, payload, result) and nudges are stored the same way; an approval's handler gets its payload with the values. Code that acts on a model's answer itself, like the browser's worker, uses `RedactingModels.withValues()`, which tools that act get as `api.models`. The vault is then the one place raw values are kept. It and the small documents that hold people's text are stored whole on every change (`checkpointWhen`), and SQLite runs with `secure_delete`, so an older copy isn't left behind in revisions or free pages.

**Values are put back where a person sees them, as that person may see them.** The server projects a room once and passes each person's copy through their `Viewer` (`@nudge/protocol/project`): every string goes through `Nudge.showTo(player, text)`, which puts back the placeholders of values the player may see, and hides values someone else owns, also where they are still written out (old history, a model that repeats one). The same goes for history pages, push previews, chat bridges, the model view, REST answers and every frame of an extension's room socket.

**A value can belong to one person.** A vault entry may have an `owner`. Values become owned only when marked: `/private`, "Hide a value" in the clients, `POST /protect {private: true}`, and every value first seen in a private message. Others then see its placeholder everywhere. The owner, or an admin, can forget a value: the entry becomes a tombstone, so its number is never reused, and from then on nobody, the model and tools included, gets it back.

**A message can be private.** Its author sees it and the answer; everyone else gets the item emptied, with `privateTo` saying who it was for, so they know there was one. The model is told in the message who may see it. What the answer leads to stays private too: tool calls learn their turn through `currentTurn()` (from the newest message, fired nudge or approval outcome of the conversation), and approvals, nudges, memory facts and watches made in a private turn are private to the same person, shown in their private turns only and decided or cancelled only by them; what a private nudge or approval leads to is private again.

**What acts later acts for whoever asked.** A tool gets the values of the player its turn acts for (`actingFor`): who sent the message, whose private turn it is, or who scheduled the nudge it answers. Nudges keep `scheduledBy`, so a public nudge's tools get its scheduler's values; nudges stored before that, and other fired inputs such as watches, act for nobody and get only values nobody owns. Approvals keep `requestedBy`, and an approved or denied action gets only values both its requester and its decider may see, which for owned values means one player asked and decided; the placeholders left are in `ApprovalRun.heldBack`, so a handler can refuse or say what it could not fill in. An approval stored without `requestedBy` gets only values nobody owns, whoever decides it.

What this doesn't do: the model knows what it was told in a private turn and might bring it up later; it is asked not to, and anything it repeats that is a value shows as a placeholder to others, but its paraphrase of a private message isn't caught. Extensions keep their own data (connector notes, browser site notes, uploaded documents) as they stored it. Task inputs and checkpoints keep what was passed when they were made.

Databases from before this change keep their raw history until `nudge db redact`, which rewrites every transcript entry and the current memory, approvals and nudges with placeholders, then vacuums the file.

Amended by ADR 22: when the detectors find more, history is rewritten once, automatically, the next time an assistant opens.

Amended: a value written another way ("ann" for "Ann") is stored under a placeholder of its own, a spelling, so history gives back exactly what was written; the model sees only the value's own placeholder for all of them (`Vault.redactForModel`), so it takes them for one person. What it writes back gets the spelling the request had after the same text (`/home/⟦NAME1⟧` becomes `/home/⟦NAME2⟧` where the request had `/home/kari`, see `SpellingsSeen`), else stays the value's own and comes back as the value was first written. Spellings share their value's owner, so who may see what doesn't change.
