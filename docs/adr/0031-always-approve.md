# 31. "Always approve" leaves a standing rule in the room

Approvals (ADR 6) ask every time. A room that runs `git status` in the terminal or calls the same MCP tool over and over gets the same question each time, and people stop reading it. So the prompt now offers "Always approve", which tells Nudge to run that kind of action in that room without asking again.

**An extension offers it, and says what it covers.** `ApprovalDraft.rule: { key?, label }` opts an approval in. The rule's key is `extension/kind`, which the extension can narrow with `key`. The terminal narrows by program, and only for a simple command: one that chains, pipes, redirects or substitutes offers nothing, and neither does `sudo`, `sh -c` or the like, since a rule for its first word would cover whatever follows. MCP narrows by server and tool, connectors by connector and method, mail by account, calendars by calendar. `label` tells people what is always approved ("terminal commands that run git"). Approvals that take inputs or a client action never offer it, since a person has to supply something. Browser and desktop confirms don't offer it either, since stopping at "Pay" or "Delete" is their whole purpose. Neither do installs, trust, peers and other one-off setup.

**Rules belong to a room.** `ApprovalsDoc` keeps `rules: { key, label, by, createdAt }[]` next to the room's approvals. Approving with `always` adds or replaces the rule for the approval's key. Anyone who may use the room sees the rules (`GET /rooms/<id>/approval-rules`) and may forget one (`DELETE …?key=`). Deleting the room drops them.

**A rule never covers a turn that read untrusted data.** `requestApproval` sets `autoBy` only when the current turn has no `untrusted` sources (ADR 20). Otherwise a page or mail could steer the model into an action people once said yes to, under circumstances they never saw. Such an approval asks as before.

**It is approved as the rule's owner, through the same path.** A covered approval is still stored pending, with `autoBy`. `RoomEvents` doesn't announce it, so nothing is pushed. Instead `Nudge` calls `Approvals.approveByRule`, which runs `decide` as `autoBy` and marks the approval `auto`. So every check still applies: an admin-only action needs its rule's owner to still be an admin, and a private one needs them to be the person it is private to. The action gets only the values its owner may see (ADR 9). When the decide fails, `autoBy` is cleared and the approval is announced for people to decide; the rule stays. The room hears how it went like any other outcome, saying a standing rule approved it. If the host stops between asking and approving, `recover()` approves the leftovers at open.
